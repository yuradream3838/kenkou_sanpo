# 発見ノート ☁️ 同期・AI閲覧 設計案（ドラフト）

最終更新: 2026-11-08（未実装・検討中）

## 0. 目的

1. スマホと PC で同じ記録を見る・編集する（健康管理アプリ `health-app` と同じく ConoHa WING 上の PHP で同期）。
2. **他の AI（Claude・ChatGPT・Gemini など）から記録を読めるようにする**（分析・振り返り・動画の構成づくり・記事化など）。
3. **写真を原寸で残す**（動画・記事づくりの素材にするため）。

## 1. 結論（先に）

| 問い | 答え |
|---|---|
| 健康管理アプリと同じ仕組み（データ全体を1つの暗号化ファイルにして版ごとに保存）でよいか | **写真がある限り、そのままでは無理**。1回20MBの上限にすぐ届き、版を残すたびに写真ごと丸ごと複製される（最大約90版）。 |
| 写真を原寸で保存して大丈夫か | **大丈夫。ただし「写真は記録データとは別のファイルとして、1回だけ送る」形にすることが条件**。容量（ベーシック 300GB）には十分収まる。 |
| AI から読めるようにできるか | できる。**AI用の読み取り専用の窓口（URL）**を別に作る。ただし健康管理アプリのような「端末で暗号化してサーバは中身を読めない」方式とは両立しにくいので、どちらを取るか決める必要がある（6章）。 |

## 2. 健康管理アプリの同期（参考）

- `sync.php`（ConoHa・nuts024.com/health/）に、端末の中で暗号化した **データ全体を1つのファイル**として送る（`put`）。サーバは中身を読めない。
- 版を残す：新しい50版＋1日1つ×30日＋1か月1つ×12か月。
- 読み取り専用トークン（v2.1）で「読めるが書けない」呼び出しができる。ただし取れるのは暗号化されたままのデータで、読むには合言葉から作る鍵が別に要る。
- 1回に送れるのは20MBまで。

→ 記録（文字）だけなら同じやり方でよいが、写真を入れると次の3つで破綻する。

1. **大きさ**：原寸の写真（1枚 3〜6MB）を数十枚入れた時点で20MBを超える。
2. **版の複製**：版ごとに写真も複製される。写真1GB × 90版 = 90GB。
3. **送る量**：メモを1行足すだけで、写真を含む全体を毎回送り直すことになる。

## 3. 写真を原寸で残すための条件

### 3-1. 容量の見積もり

| 前提 | 量 |
|---|---|
| 原寸の写真 1枚 | 約 4MB（スマホの 12MP JPEG／HEIC） |
| 1回の散歩 | 10枚 → 約 40MB |
| 週3回 × 1年 | 約 6GB／年 |
| ConoHa WING ベーシック | 300GB（他のサイト・健康管理アプリと共用） |

→ 原寸でも **数十年分**は入る。容量そのものは問題にならない。

### 3-2. 守るべき設計

1. **写真は1枚ずつ別のファイル**としてサーバに置く。記録データ（JSON）には写真の ID だけを書く。
2. **写真は変更しない・版を作らない**。ID は写真の中身から作る（SHA-256）ので、同じ写真を2回送っても1つになる。送り直しても安全。
3. **サイズ違いをサーバで持つ**：
   - `orig`：原寸（撮ったまま。HEIC ならそのまま）— 素材用。
   - `large`：長い辺 2048px の JPEG（撮影位置などの情報を消したもの）— PC表示・AI用。
   - `thumb`：360px — 一覧用。
   - `large`／`thumb` はスマホで作って一緒に送る（サーバで画像変換をしなくて済む。HEIC もスマホのブラウザが読めればここで JPEG にできる）。
4. **スマホには原寸を残し続けない**。送り終えた原寸は端末から消し、表示用（1600px）と一覧用だけを残す（ブラウザの保存容量の上限・iPhone の自動削除への対策）。
5. **送る量への配慮**：原寸は 1枚 4MB なので、1回の散歩で 40MB ほど。設定で「原寸はあとでまとめて送る（Wi-Fi のときに手動で）」を選べるようにする。記録と小さい写真は先に送る。
6. **PHP の上限を確認**：`upload_max_filesize`・`post_max_size` が写真1枚より大きいこと（PHP 初期値は 2MB。ConoHa のコントロールパネル「PHP設定」で変えられる）。足りなければ写真を分割して送る方式にする。
7. **原寸の写真はサーバにしかない状態になる**ので、二重に持つ：PC 側で「原寸の写真をフォルダに保存」できるようにする（＋ ConoHa の自動バックアップ。保存期間はコントロールパネルで確認）。

## 4. 全体の構成

```
[スマホ PWA] ──記録(JSON)・写真──▶ [ConoHa: sanpo/sync.php] ◀── [PC（同じ PWA をブラウザで開く）]
                                         │
                                         ├─ data/records/…      記録（1件1ファイル）
                                         ├─ data/photos/{id}/   orig / large / thumb
                                         └─ data/changes.log    変更の番号つき一覧
                                         │
                                  [sanpo/ai.php] ◀── 読み取り専用トークン ── [他の AI]
```

- 健康管理アプリとは **フォルダもトークンも分ける**（`/sanpo/`）。片方の合言葉が漏れても、もう片方は守られる。
- 置き場所の例：`https://nuts024.com/sanpo/sync.php`、`https://nuts024.com/sanpo/ai.php`

## 5. 同期のしかた（データ全体ではなく1件ずつ）

健康管理アプリの「全体を1ファイル」ではなく、**1件ずつ・変わったものだけ**送る方式にする。

- 単位：発見1件・おでかけ1件・写真1枚。それぞれ `id` と `updatedAt` を持つ（今のデータにすでにある）。
- 消したとき：消した印（`deleted: true` と時刻）を残して送る（ほかの端末からも消えるように）。
- サーバは変更のたびに通し番号（`rev`）を振る。端末は「最後に受け取った番号」以降の変更だけ取りに行く。
- ぶつかったとき（同じ発見を2台で編集）：**時刻が新しいほうを残す**。上書きされた側は「以前の版」として1件ごとに残す（数版まで）。1人で使う前提なので、健康管理アプリの項目ごとの混ぜ方より単純で足りる。
- 送るタイミング：保存して少したったら／アプリを閉じたとき／開いたとき・画面に戻ったときに取りに行く（健康管理アプリと同じ）。
- 電波がないとき：送る予定を端末にためておき、つながったら送る。

### 5-1. sync.php の操作（案）

| a | メソッド | 内容 |
|---|---|---|
| `changes&since=N` | GET | 番号 N より後の変更（記録の中身ごと） |
| `put` | POST | 記録1件以上をまとめて送る（JSON）。`baseUpdatedAt` が古ければ 409 と最新を返す |
| `photo&id=&size=` | GET | 写真（orig／large／thumb） |
| `pput&id=&size=` | POST | 写真を送る（本文は画像そのもの）。同じ id がすでにあれば何もしない |
| `pmissing` | POST | 「この id の写真、サーバにありますか」→ 無いものだけ返す（原寸をあとで送るときに使う） |
| `snapshot` | GET | 全記録の JSON（PC での丸ごとバックアップ用） |

- 認証：書ける合言葉（アプリ用）と、読むだけのトークン（AI 用）を分ける（健康管理アプリ v2.1 と同じ考え方）。
- `ALLOWED_ORIGINS` に `https://yuradream3838.github.io`。

## 6. AI から読めるようにする（要決定）

### 6-1. 2つの方式

| | A. 端末で暗号化（健康管理アプリと同じ） | B. サーバに読める形で置く（トークンで守る） |
|---|---|---|
| サーバが乗っ取られたとき | 中身は読まれない | 記録・写真・場所が読まれる |
| AI から読む | AI は鍵がないと読めない。**PC で復号して渡す係**が要る（6-3） | **URL を渡すだけ**でどの AI でも読める |
| 写真の扱い | 写真も暗号化（AI には PC 経由で渡す） | `large` をそのまま AI が見られる |
| 作る手間 | 大きい | 小さい |

### 6-2. おすすめ：**B（読める形で置く）＋ 守りを足す**

散歩の記録は健康の記録ほど機微ではなく、目的が「AI に見せる」ことなので B が合う。ただし「どこに住んでいるか」が分かる情報（場所・時刻のくせ）は守る。

- **AI 用のトークンは読むだけ・いつでも作り直せる**（漏れても書き換え・削除はできない。作り直せば古い URL は使えなくなる）。
- **自宅の周りをぼかす**：設定で「自宅の周り（半径○m）」を決めると、AI 用の窓口ではその範囲の場所を丸めて出す（例：500m 単位）。
- **AI に見せない印**：発見ごとに「AI に見せない」を付けられる。
- **AI 用の写真は `large`（撮影位置などの情報を消したもの）だけ**。原寸（位置情報入り）はアプリ用の合言葉でしか取れない。
- サーバの `data/` は `.htaccess` で直接は見えないようにする。

### 6-3. （A を選ぶ場合）PC に「読み出し係」を置く

PC で小さなプログラム（または MCP サーバ）を動かし、合言葉で復号して、Markdown と写真のフォルダに書き出す。Claude Code・ChatGPT のデスクトップアプリなど、**PC のファイルを読める AI** から見られる。スマホの AI アプリや Web 版の AI からは見られない。

### 6-4. AI 用の窓口 `ai.php`（B の場合）

AI は特別なヘッダを付けられないことが多いので、**トークンを URL に含める**形にする（例：`https://nuts024.com/sanpo/ai.php?t=トークン`）。

| URL | 返すもの |
|---|---|
| `ai.php?t=…` | **AI 向けの案内（Markdown）**：このデータが何か・各項目の意味・ほかの URL の一覧・最近の散歩と発見の要約 |
| `…&a=walks` | おでかけ（散歩）の一覧：日付・駅・目的・散歩時間・発見数・メモ |
| `…&a=walk&id=` | 1回の散歩：タイムライン（時刻つきメモ・発見）と写真の URL |
| `…&a=finds&cat=&feel=&from=&to=` | 発見の一覧（種類・気持ち・期間で絞り込み） |
| `…&a=find&id=` | 発見1件：気づき・仮説・調べたこと・出典・写真の URL |
| `…&a=search&q=` | キーワード検索 |
| `…&a=img&id=&size=large` | 写真（AI 用の `large`／`thumb` だけ） |
| `…&fmt=json` | どれも JSON でも返せる（プログラムや MCP から使う用） |

- 既定は **Markdown**（AI が読みやすい）。日時は日本時間で書く。
- 一度に返す量は抑える（新しい順に50件・続きは `&page=`）。

### 6-5. 将来：MCP サーバ

Claude などは「MCP サーバ」をつなぐと道具として呼べる。`ai.php` の JSON をそのまま使う小さな MCP サーバを用意すれば、「先月見つけた暗渠を一覧にして」のように AI から直接聞ける。まずは 6-4 の URL で十分。

## 7. アプリ側の変更（実装するとき）

1. データ：発見・おでかけに `updatedAt`（あり）・`deleted`（消した印）を付ける。写真に `hash`（SHA-256）を付ける。
2. 写真：選んだ／撮った時点で、原寸（そのまま）・`large`（2048px）・`display`（1600px）・`thumb` を作る。原寸は「送る予定」に入れ、送れたら端末から消す。
3. ⚙設定に「☁️ ConoHa 同期」：サーバの URL・合言葉・端末の名前・原寸を送るタイミング・AI 用トークンの発行／作り直し・自宅の周り。
4. PC：同じ PWA をブラウザで開いて同じ合言葉を入れる。「原寸の写真をフォルダに保存」ボタン。
5. 発見の詳細に「AI に見せない」。
6. テスト：`server/sync.php.example` を PHP の組み込みサーバで動かし、2つのブラウザで 送る・受け取る・同時に編集・消す・写真の送り直し・原寸をあとで送る・AI 窓口の絞り込みとぼかし・読み取り専用で書けないこと を確かめる（健康管理アプリの `test/sync.js` と同じやり方）。

## 8. 決めること

1. **AI 閲覧の方式**：B（読める形で置く・おすすめ）か A（暗号化して PC で読み出す）か。
2. **原寸の写真を送るタイミング**：すぐ送る／あとでまとめて（Wi-Fi のとき手動）。
3. **原寸として残すもの**：撮ったまま（位置情報入り）か、位置情報だけ消すか。
4. **自宅の周りのぼかし**を使うか（使うなら中心と半径）。

## 9. ConoHa で確かめること

- PHP の `upload_max_filesize`・`post_max_size`（写真1枚以上か）— コントロールパネル「PHP設定」または `phpinfo()`。
- 自動バックアップの保存期間（コントロールパネル）。
- `nuts024.com` に `/sanpo/` フォルダを作れること（`sync_data` と同じく `.htaccess` で `data/` を守る）。
